# Five-minute demo

## 00:00–00:25 — Problem and scope

Show the standalone plugin and state: Cloud Server only, no WooCommerce/page builder dependency, no official-partnership claim.

## 00:25–00:55 — Install and protected setup

Open the setup wizard. Show Mock/Live badge, Machine User password field, stored-state indicator, and read-only test. Do not display or paste a key.

## 00:55–01:25 — Customer and Mock top-up

Sign in with WordPress, open the mobile-ready portal, create a Mock payment, confirm it, and show the wallet plus immutable transaction history.

## 01:25–02:10 — Configure and estimate

Open Create Server. Select REST-provided region, image, and flavor. Set server name/options. Show the authoritative 24-hour backend estimate and exact currency code.

## 02:10–02:55 — Provision and Resource ID

Confirm Mock provisioning. Show the finite timeline, completed order, copyable LTR Resource ID, and service status. Mention that Live provisioning is never automatic.

## 02:55–03:35 — Usage and financial model

Show usage chart plus accessible table, base cost, reseller share, charged/uncovered amounts, wallet ledger, and invoices. Explain exact UTC windows and stored hourly price.

## 03:35–04:00 — Low balance and lifecycle

Show the low-balance alert and configured zero-balance policy. Explain that suspension uses supported power-off behavior and is not claimed as a guaranteed external billing freeze. Show termination as a distinct policy.

## 04:00–04:25 — Admin operations

Show dashboard, health, protected Cron/reconciliation confirmation, audit log, and **SIMULATED / INTERNAL ACCOUNTING** settlement report. Never imply an external payout.

## 04:25–04:45 — Mobile

At 375px, show wallet hero, active server, Create Server action, alerts, drawer, and four-item bottom navigation without horizontal page scrolling.

## 04:45–05:00 — Architecture and limitations

Show native WordPress authentication, one nonce-aware REST client, scoped CSS, no runtime CDN, and the GitHub branch. State the official per-server usage/settlement limitations and the known safe-serializer contract gaps.
